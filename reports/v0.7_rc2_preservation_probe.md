# v0.7.0-rc.2 source-preserving write-back probe

Conclusion: **one real paragraph can be replaced on a copy of the original page without changing its other visible content; the full PDF is not yet formally usable**.

## What changed

The old BabelDOC replay on physical page 42 retained 32 of 50 recognizable mathematical-font glyphs. The rc.2 editor instead locates the complete section 2.2 opening paragraph, clears exactly six original `TJ` text-show operations, leaves the separate footnote number operation intact, and inserts the two-sentence Chinese translation using an embedded FangSong font. Ambiguous matches, overlapping unchanged glyphs/graphics, unsupported page content, or any post-edit fidelity failure stop the operation. A temporary PDF is published only after reopening and rechecking it; an existing destination is never overwritten.

- Source SHA-256: `297196f2cad5ab23cf4855f815fd69e7b7b9ee9c31255f743b668416677ad24e`.
- The exact English phrases were located uniquely before editing. The Chinese paragraph contains the complete discrete/continuous distinction, not a separate rendering of “There are”.
- After saving, page geometry, zero raster images, all five vector paths, and all 50 recognizable math-font glyphs matched the source. All glyphs outside the target slots matched in character, font, size, origin and bounding box.
- At 2× rasterization, changed pixels outside the exact target slots plus a documented 0.25 pt text-antialias margin: **0**. The page was also rendered and visually checked. No DeepSeek API call was made in this rc.2 probe.
- Six new component tests passed, including a synthetic PDF with a neighboring formula and vector drawing, missing/overlapping text-operation failure cases, pixel-difference fault injection, and refusal to overwrite an existing output.

## Limits and next gate

This is a one-paragraph proof, not a finished page: other English prose remains. The editor supports only an exact source phrase mapped to complete `Tm ... TJ` operations in one source content stream, with predeclared Chinese placement. The current capture data is not yet precise enough to generate every edit automatically, especially around inline formulas, footnotes and low-confidence locations. It has not demonstrated multi-page or multi-book coverage, nor independently reviewed all source/target meanings. `formal_use_ready` therefore remains false. The next implementation gate is automatic source-operation mapping with protected-inline-content checks, followed by complete-page preservation and semantic review.
