# v0.6.0-rc.1 real-PDF context candidate acceptance

Date: 2026-09-11

## Verdict

Status: **release candidate accepted for offline structure and reliability; paid translation quality is not accepted**.

The candidate is eligible for tag `v0.6.0-rc.1`. It is not eligible for stable `v0.6.0` until a controlled DeepSeek A/B run and human quality review are completed.

## Implemented

- Every external provider attempt is recorded before schema, result identity or quality validation can fail.
- Attempt records include outcome, failure category, response ID when available, token usage and cost.
- Invalid structured responses and critical protected/layout-marker failures have a persisted retry limit of one to three attempts; default is two.
- Missing API keys fail before any attempt is charged.
- Captured PDF units receive nested chapter/section paths and deterministic previous/next context links.
- Context links cross a page boundary only for consecutive physical pages; disjoint benchmark samples cannot leak context.
- Neighbor excerpts are capped before deterministic context-budget selection.
- Captured-workload estimates include routed V1 context rather than the V0 fixed-context approximation.
- Dedicated commands initialize context from captured document identity, inspect captured-context ablation, capture development pages without model calls, and run only the development sample.

## Automated reliability evidence

- Full suite: 49 tests passed.
- Fault injection verifies that an invalid billable schema response is charged before a successful retry.
- Fault injection verifies that two failed attempts remain exhausted after resume.
- Fault injection verifies that a critical protected-marker failure is charged and retried.
- Context tests verify reading order, nested headings, consecutive-page links, protected-unit exclusion and nonconsecutive-page isolation.
