# v0.7 rc12：先修输入与上下文质量

用户已授权继续优化，并要求真实 API 翻译。沿用其选定的 18 页 CS224n 讲义，保留 rc11 原始捕获、译稿与数据库，rc12 独立运行。

优先级：
1. 公式、代码、数字等原文对象的内容、字体、大小和位置不变是验收硬条件。未满足时只能输出审阅草稿；不能用翻译准确或 API 成功抵消。
2. 先修可定位的文档提取、语义切分、上下文组装、写回问题。模型本身的表达能力问题后置。
3. 流程提速和成本优化不作为本轮优化目标。

本轮实施：
- 原文有显式行末断词、连续物理页、同栏、底部→顶部且定位可靠时，合并两页的纯文本单元，恢复完整英语词后再翻译。带公式、低定位置信度、非连续页及已有语义组不自动合并。
- 几何条件不能证明连字符必然是软断词，真正的复合词连字符仍需语义复核；本次 equivalently 与 velocity 已逐一核对。
- 原始捕获不变；派生单元有独立 ID、来源、哈希和父单元映射。
- 以重复顶栏及位置证据排除页眉；正文相邻上下文不被旁注替代。前文取结尾、后文取开头。
- 写回在整个文档范围内分配语义单元的各个版面片段，避免跨页重复全文。
- 用同一个 deepseek-flash 模型先做两组真实 API 小样，再跑 18 页，独立逐页检查。估算全量上限 USD 0.151533；运行硬预算 USD 0.20；小样预算 USD 0.02。

验收：两个已确认跨页坏例必须恢复完整含义；译文不得在两页重复；页数与原文对象继续严格校验。保留单元、服务器响应 ID、用量、源/目标渲染、逐页结果。语言小样通过不能外推为整份讲义通过。

仍须继续解决的源头问题：行内公式没有整体识别为不可变对象；编号步骤被扁平化；部分页眉字母被误识别成公式；普通跨页句子没有显式断词时尚未自动合并；缺少可验证公式字面量使模型看不到部分关系。不得把这些问题归因于模型能力。
